# 一图流 PV：一张插画在 Blender 里做成 2.5D

一张插画 + 一首歌，做成可以发 B 站的鉴赏 PV。思路是把插画按深度拆层、摆进 Blender 成为有真实视差的场景，
镜头在里面缓慢运动，人物局部变形（头发、尾巴随风，嘴跟着唱），再加跟着音乐走的粒子、光效和旋律盘。
所有步骤都在 AutoDL 的 4090 D 上跑，本地不装、不跑任何东西。

## 流程

| 步骤 | 脚本 | 在哪跑 |
|---|---|---|
| 服务器环境：依赖装进单独的 `pv/pylib`（借用 ComfyUI venv 的 torch / transformers / spandrel），模型下到 `pv/models` | `scripts/onepic_setup.sh` | AutoDL |
| 逐帧音频特征：节拍、重拍、恒速的拍子网格（每首歌自己量）、响度、低频、高频、人声（慢的和跟字的快包络），48 段对数频谱 | `scripts/audio_bands.py` | AutoDL（evalq 环境有 librosa） |
| 插画 -> 深度（Depth Anything V2 Large）、人物遮罩（anime-seg ISNet）、补全背景（LaMa）、天空范围、星点、月亮 | `scripts/onepic_prep.py` | AutoDL |
| 接入另外做好的分层（远 / 中 / 近 / 人物），每层可用 2x-AnimeSharpV4 放大 2 倍 | `onepic_prep.py layers` | AutoDL |
| 插画局部画坏了（手、道具）：Qwen 局部 img2img 只重画一个框，再放进 prep 和人物层 | `scripts/retouch.py`、`scripts/retouch_apply.py` | AutoDL |
| 人物各部位的摆动权重（头发、耳朵、尾巴、裙摆、嘴、呼吸），位置写在 case 的 `rig.json` | `onepic_prep.py rig` | AutoDL |
| Blender 场景：层网格、人物变形、粒子、频谱环、流星、标题、镜头、合成 | `scripts/onepic.py` + case 的 `pv.py` | AutoDL |
| 左下角的旋律盘：唱片、频谱、歌名、进度条，逐帧透明 PNG | `scripts/onepic_player.py` | AutoDL |
| 分段渲染（任务队列，断了能续） | case 的 `render.sh` | AutoDL |
| LRC 歌词 + 制作信息 -> ASS | `scripts/lrc2ass.py` | AutoDL |
| 分段拼接，一次编码成片：颗粒、暗角、淡入淡出、字幕、音轨 | `scripts/onepic_finish.py` | AutoDL |

## Blender 场景（`onepic.py`）

- **层网格**：原始机位在原点看 +Y。每层是一张网格，顶点 (u, v) 沿原始机位的视线放到该点的距离，UV 就是插画坐标，
  所以从原始机位看和原画逐像素一致，镜头一动就有真实视差。距离由视差换算：人物的中位视差 -> `y_girl`（1.6 m），
  天空 -> `y_sky`（220 m），视差和 1/距离 成正比，两点之间线性插值。
- **材质**：Emission 原样输出贴图，视图变换用 Standard，插画颜色不被色调映射改动。贴图在画外**镜像**延伸（`MIRROR`），
  网格往外多铺 8%：镜头斜着仰拍时四角会超出原画，镜像出去的星空和花田看不出来，`EXTEND` 会拉出条纹。
- **音频数据贴图**：逐帧的量（频谱各段、段落强度、风时间……）存成一张浮点贴图，每帧一行、每个量一列，帧数多时折成几块并排
  （GPU 贴图边长有上限）。着色器里用驱动器写入当前帧，Geometry Nodes 里用 Scene Time，按帧去查。
- **粒子**：位置只由时间和随机种子算出来（初始位置 + 风 × 风时间 + 正弦摆动，出盒子从对面回来），不用模拟，所以任意一段帧都能单独渲染。
  "风时间"是风速的累积，段落强时花瓣飘得快但不会跳。开着的粒子比例由一列 density 控制。
- **镜头**：pose 用插画坐标写（对准哪一点、放大多少、机位离开原点几厘米）。推荐 `Camera.bake(keys=...)`：
  一条不断开的路径，关键帧放在段落交界，每个参数用单调三次插值（pchip）过渡，速度连续、不冲过关键帧；
  对焦按屈光度（1/距离）插值，焦点从月亮换到脸是一路拉过来的。`Camera.bake(shots=...)` 是分段 + 缓动的旧写法。
  景深用 `blur` 写：场景里最大的虚化占画面宽的比例，按焦距和对焦距离反解光圈，对焦在远处时近处的人物也不会糊成一片。
  `Camera.check()` 列出画面四角超出插画（加网格余量）的时间段。
- **人物变形**（`deform()`）：人物层的网格顶点存着自己的插画坐标和各部位权重，Geometry Nodes 按时间算位移
  （在插画坐标里算，再按顶点距离换成米）：头发是从发根往下传的波，尾巴绕根部转，耳朵按两列动作曲线往外、往上张，
  嘴按人声快包络以嘴为中心伸缩，胸口和肩膀按 `breath` 列呼吸。贴图跟着网格走，像 Live2D；被挡住的地方远景层补过，拉开不露底。
- **可选特效**：镜头前的虚焦光斑或花瓣（`bokeh_mat` 或 `bokeh_petal_mat` + `drift`）、朝月亮的轮廓光（`rim_extra`）、重拍上的轻推（`Camera.bake` 的 `kick`）、
  月亮的水平光条（`compositor(streak=True)`）、发饰的四芒星（`glints`）。case 的 `pv.py` 用 `FX=` 环境变量开。
- **月光光束**（`compositor()`）：画面乘一个跟着月亮走的椭圆遮罩再做 Sun Beams，只把光束加回去。不加遮罩时
  白裙子、亮的花也会拉出光束扫过人物，强度不敢开大；加了遮罩可以开到整片天空都有放射的光。
- **开头的虚化用真焦外**：标题放到镜头前半米，对焦在标题上，人物和背景一起落在焦外；焦点拉回来就清楚了。
  `Camera.path` 的关键帧可以只写 focus / focus_m / blur，对焦单独插值。
- **旋律盘**：画里有月亮的话，月亮外圈就是旋律盘。星环（`star_ring()` + `scripts/star_ring.py`）：月亮是唱片的标签，
  光点沿看不见的轨道绕着转，出现、明灭、转速跟着各段频率；逐帧的角度、亮度存成一张数据贴图，Geometry Nodes 按帧
  （尾巴按往前的帧）查，摆在天空前面，人物、花瓣会挡住它。或者频谱环（`spectrum_ring(pulse=...)`），低音来时整圈鼓起来；
  `tilt` 让朝人物那边的柱子长一点，`squeeze` 压短反方向，`top` 把朝上的柱子软压在画框里。
  左下角的歌名、进度条和时间（`onepic_player.py`）是多进程 PIL 逐帧画的透明 PNG（只画那一块），收尾时 overlay；
  后面垫一块柔边的半透明深色底板，花田很亮时文字也看得清。给 `--art` 时它自己也画一个带唱片的旋律盘，画里没有合适的圆形主体时用。
  `--show` 让它只在一段时间里出现，给开头的大标题和结尾的制作信息让开。

## 踩过的坑

- **运镜**：第一版每十几秒硬切到完全不同的构图、每段都加速减速停住、特写放大到 3 倍、重拍上推镜加手持晃动，
  看起来又乱又机械。第二版改成一条连续的路径，但主歌推近她、C 段推到脸（1.7 倍），还是不稳。
  一图流要的是整首都看整张画：放大只在 1.04–1.10 倍之间，中心只在正中附近漂，动感交给机位平移带出的视差。
- **两个旋律盘**：画里的月亮一圈频谱、左下角又一个带唱片的盘，同时跳就抢眼。镜头不推近时月亮一直在画面里，旋律盘就交给月亮。
- **先出低清预览再出成片**：540p、30 fps、8 采样整首几分钟就有，先拿它定运镜和节奏，再花两个多小时出 4K60。
- **比样式时在画面上叠 2D 的光，定了马上做进场景**：在渲好的帧上用 numpy / OpenCV 画光、滤色叠上去，改一版几分钟
  就能看，适合一轮轮比样式。但它挡不住人物（从她身后过的轨道画在她身上），也全靠 CPU：盘画到半个画面时
  画布近 4000 px 见方，一帧十几秒，AutoDL 的 18 核配额一挤就更慢。定了就做进 Blender，按帧查数据贴图，GPU 渲。
- **歌名一次只在一处**：开头的大标题、左下角的歌名栏、结尾的制作信息里都有歌名，歌名栏从头到尾都在，就和另外两个各重了
  十几秒。排成接力：大标题淡出后歌名栏才进来，歌名栏淡出后制作信息才出，接的地方都落在段落的重拍上。
- **星环的尾巴别压着别人**：同一道轨道上的光点快慢不一、尾巴又长，没管的时候一半时间里有光头落在别人的尾巴上，
  看着像一串追尾。后面的追近时把前面那颗的尾巴收短（收短立刻、放长按尾巴自己的时长），外圈光点密的轨道尾巴再短一点。
- **拍子网格每首歌自己量**：librosa 的 beat_track 常测成倍频（一首 165 BPM 的歌测成 109）。`audio_bands.py` 的
  `beat_grid()` 在自相关的几个峰和它们的 2、1/2、3/2、2/3 倍附近细搜恒速网格，再按拍点 / 反拍挑对的那一档。
- **嘴的位置**：按颜色在给定位置附近找嘴里那块暗红，比手估的准（这次偏了 0.01）。
- **头发和裙子分不开**：白裙子的阴影带淡紫，会被颜色判成头发，权重一块一块的会让裙子局部乱扭；
  裙子正中那一竖条按位置全归裙摆。
- **半透明的袖子**：后面透出头发，按颜色会当成头发，头发一摆，上臂的袖子也跟着扭。在 case 的 `rig.json` 里给袖子
  画多边形（`sleeves`），里面头发权重为 0；出了袖子按距离慢慢放开，贴着袖子的发丝不会被挤出一道折痕。
- **抠图的半透明**：分层抠出来的人物，尾巴、几缕头发的 alpha 只有 0.6–0.9，渲染时后面的花从里面透出来，看着像糊了
  （关景深、关合成都还在，把混合系数写死成 1 才干净）。`rig` 最后把人物内部的 alpha 补满，边缘和细发丝不动，
  case 指定的本来该透的地方（透出花的裙边）也不动。
- **硬物不能跟着变形**：话筒线垂在裙子上，跟着裙摆摆会弯；话筒头挨着下巴，跟着嘴伸缩会歪；头发权重模糊时会渗回手上，
  手指边跟着晃。皮肤和深色硬物（话筒、线、颈带）在所有权重里都乘一次 (1 − rigid)，放在最后一次模糊之后。
  细长的硬物（越往下越细越浅的话筒线）按颜色抓不全，在 case 的 `rig.json` 里画成折线（`rigid`）。
- **幅度要按 4K 像素量**：在 Blender 里取变形后的网格和原位置比，换算成 4K 画面上的像素；540p 预览里只有四分之一。
- **呼吸只动胸口和肩膀**：整个人以下边为轴伸缩，头跟着一点一点的，像假的。按歌词的句子吸气、呼气比固定周期自然。
- **耳朵别抖太快**：7 Hz、0.16 秒衰减的抖动又快又突然；3 Hz、0.28 秒衰减、0.08 秒起手，加上一直在的慢摆，才像耳朵。
  耳朵框里压着的发饰要单独排除，不然跟着耳朵扭。
- **月亮不跟着闪**：月晕、光束直接跟低音会一下一下地闪。用低音平方的 0.3 秒滑动平均、幅度小一些；月亮圆盘本身保持一个亮度。
- **开头别先清楚再虚**：歌名出来时才把焦点拉到标题上，看着像对焦失误；第一帧就对在标题上。
- **局部重画的强度**：Qwen 的 img2img 在 0.9 以下保留原图结构（手的姿势、道具的角度），歪的话筒照样歪；要改结构就开到 1.0 整框重画，
  或者先把框里的东西转正再 0.75–0.9 重画。

- **Depth Anything 对插画**：远处的花田估得和天空一样远，角上的大花估得比人物还远。天空改用颜色判定（大范围平均亮度低的深色区域），
  近景层的 1/距离 乘 2.2 拉近。
- **z-fighting**：补全过的远景层自己也有一整片花田，深度和中景层几乎相同，两张网格叠在一起闪出块状花纹。远景层整体往后推 20% 就好了。
- **星点闪烁**要从挂效果的那一层自己提取：被挡住的地方重画过，星星位置和原图不同，按原图的星点去调亮度会在没有星星处压出黑点。
  闪烁也以变亮为主。
- **对焦点落在缝里**：全景对准 (0.52, 0.5) 时正好是头发之间的天空，镜头对焦到无穷远，人物全糊。焦点默认放在脸上。
- **透明层放大前先渗色**：直通 alpha 的 PNG 透明处颜色是黑的，放大和贴图过滤会把黑色混进边缘。用 push-pull（逐级缩小再放大）
  把附近的颜色填进透明处，几秒钟；大半径高斯模糊在 4K 上要几十分钟。
- **4K60 的渲染速度**：单个 EEVEE 进程约 0.9 秒一帧，大头是每帧固定的 CPU 开销（采样从 32 降到 8 几乎不变）。
  几个进程并行时 GPU 先满（4 个就 99%），合计约 0.4 秒一帧，5 分半的歌两个多小时。
- **进程被无声杀掉**：每个 Blender 进程渲到稳定后约 9.5 GB 内存、3.4 GB 显存。AutoDL 容器的内存上限是 64 GB
  （`/sys/fs/cgroup/memory.max`，`free` 看到的是宿主机），6 个进程会被 OOM 杀掉，日志只停在半帧、不报错。
  所以用 4 个进程，切成 10 秒一段的小段排队，每段完成留 `.done`，断了只补没完成的。
- **Whisper 转歌词**切句很差，歌词用 LRC 做 ASS 字幕在最后一步烧进去，改字幕不用重渲染。
- **服务器上停进程**：`pkill -f <模式>` 会匹配到自己这条 ssh 命令把连接杀掉；用 `pkill -x blender` 按进程名，或者 `pgrep -f "^bash ..."` 锚定开头。
  正在运行的 bash 脚本不要覆盖（bash 边执行边读文件）。
